\## Что это



`strscan` — утилита для поиска подозрительных строк в скриптах Windows:

`.bat`/`.cmd`, PowerShell `.ps1`, VBScript, JScript, HTA.



Пользователь ведёт свою базу подозрительных строк (простой текстовый

файл), утилита сканирует файлы, нормализует текст (нижний регистр,

убирает пробелы, убирает комментарии) и показывает, какие строки

и где найдены.



\*\*Это не антивирус.\*\* Утилита не выносит вердиктов «вирус / не вирус».

Она показывает факты: «в файле X найдены строки A, B, C». Решение —

за пользователем.



Типичные сценарии:

\- проверить папку с подозрительным скриптом;

\- найти USB-червя на флешке (проверить `autorun.inf`);

\- поискать в автозагрузке вредоносные `.bat` / `.vbs`;

\- просканировать систему на известные техники зловредов

&#x20; (самокопирование, правка реестра, загрузка из сети).



\---



\## Как это работает



1\. Берётся текстовый скрипт.

2\. Декодируется (UTF-8, CP866, UTF-16, BOM).

3\. \*\*Нормализуется:\*\*

&#x20;  - строки-комментарии пропускаются целиком;

&#x20;  - остальные строки приводятся к нижнему регистру;

&#x20;  - из строк убираются все пробелы и табы.

4\. Ищутся строки из пользовательской базы (по секциям — для разных языков).

5\. Показываются найденные строки с номерами.



\### Зачем это нужно



`.bat`-вирус может меняться при каждом запуске:



```bat

echo rem %random% %random% >> "%\~f0"



Это меняет хеш файла (обход хеш-сигнатур), но полезная нагрузка

(copy %0, reg add) остаётся неизменной. Нормализация убирает

мусор — и мы находим команды зловреда.



Что не работает

Конкатенация через set:



bat

set a=co

set b=py

%a%%b% %0

Нормализация это не разворачивает.



Шифрование всего скрипта (base64-обфускация).

Найти можно только по загрузчику (powershell-enc и т.п.).



База строк

База — простой текстовый файл с секциями:



text

\[all]

downloadstring



\[bat]

copy%0

regadd

disabletaskmgr



\[ps1]

powershell-enc

invoke-expression

Секции

\[all] — паттерны для всех языков



\[bat] — только для .bat / .cmd



\[ps1] — только для .ps1 / .psm1 / .psd1



\[vbs] — только для .vbs / .vbe



\[js] — только для .js / .jse / .wsf / .wsh



\[hta] — только для .hta



При сканировании файла выбираются паттерны из \[all] + секция,

соответствующая языку файла. Паттерны из \[ps1] не ищутся в .bat,

и наоборот.



Формат

text

\# Комментарии начинаются с #

\# Пустые строки игнорируются



\[all]

frombase64string



\[bat]

copy%0

regadd

Хранение:



Строки хранятся как есть (с пробелами, если так написали).



Нормализация применяется только при поиске.



Дубликаты проверяются по нормализованной форме: copy %0 и COPY%0

считаются одинаковыми.



Важно: комментарии в теле файла (между паттернами) не сохраняются

при редактировании через CLI (strings add / strings remove).

Комментарии в шапке — сохраняются.



Широкие паттерны #wide:

Часть паттернов помечена префиксом #wide: — они выключены по умолчанию.



Это широкие паттерны: используются и зловредами, и легитимными

программами. Например:



frombase64string — есть в Office, диагностике, PowerShell-модулях,

и в зловредах для декодирования полезной нагрузки.



invoke-expression — есть в VS Code, легитимных модулях,

и в зловредах для запуска скачанного кода.



\-encodedcommand — есть в Secure Boot и MS-скриптах,

и в зловредах для обфускации.



В дефолтном режиме такие паттерны выключены, чтобы не давать FP.



Чтобы включить — уберите префикс:



text

было:  #wide:invoke-expression

стало: invoke-expression

Список широких паттернов:



Секция	Паттерны

\[all]	frombase64string, -encodedcommand

\[ps1]	-executionpolicybypass, invoke-expression, iex(, invoke-webrequest, -nop, -noprofile

\[vbs]	createobject("wscript.shell"), wscript.shell

\[js]	activexobject(, wscript.shell, savetofile

В \[bat] широких паттернов нет — .bat-паттерны специфичны, FP почти

не дают. В \[hta] wscript.shell оставлен активным — HTAs редки,

FP мало.



Быстрый старт

Скопируйте strscan.exe в удобную папку:



text

C:\\Tools\\strscan\\

Рядом создайте папку strings\\:



text

C:\\Tools\\strscan\\strings\\

Скопируйте в неё дефолтную базу default.txt (если она есть в поставке).



Добавить паттерн в базу:



cmd

strscan.exe strings add "copy%0" --section bat

Посмотреть, что в базе:



cmd

strscan.exe strings list

Проверить один файл:



cmd

strscan.exe check suspicious.bat

Просканировать папку:



cmd

strscan.exe scan C:\\Users\\user\\Downloads --progress

С контекстом (показать строки до/после):



cmd

strscan.exe check suspicious.bat --context 2

Команды

scan <path>

Просканировать файл или папку по базе строк.



text

\--strings FILE      база строк (по умолчанию strings\\bad\_commands.txt)

\--ext LIST          расширения через запятую

\--no-normalize      не нормализовать текст (точное совпадение)

\--context N         печатать N строк контекста до/после

\--min-hits N        показывать файлы с >= N совпадений (1)

\--skip DIRS         пропустить папки (через запятую)

\--min-size SIZE     минимальный размер файла (1K, 100M)

\--max-size SIZE     максимальный размер файла (1M, 2G)

\--limit N           остановиться после N файлов

\--progress          печатать счётчик

\--quiet             не печатать оригинальную строку и контекст

\--log FILE          лог в файл

\--encoding ENC      принудительная кодировка (utf-8, cp866, cp1251)

check <file>

Проверить один файл (без рекурсии).



text

\--strings FILE      база строк

\--context N         печатать N строк контекста

\--no-normalize      не нормализовать

\--encoding ENC      принудительная кодировка

strings list

Показать содержимое базы строк, разбитое по секциям.



strings add <line>

Добавить строку в базу (если её там нет).



text

\--section SEC       секция (all/bat/ps1/vbs/js/hta; по умолчанию all)

strings remove <line>

Удалить строку из базы (из всех секций).



strings check <line>

Проверить наличие строки в базе.



Все подкоманды strings принимают --strings FILE.



Расширения по умолчанию

strscan по умолчанию сканирует только реально исполняемые Windows

скрипты — то, что запускается по двойному клику или через WSH:



text

.bat .cmd         — командные файлы

.ps1 .psm1 .psd1  — PowerShell

.vbs .vbe         — VBScript

.js .jse          — JScript

.wsf .wsh         — Windows Script Host

.hta              — HTML Application

Текстовые данные (.txt, .log, .ini, .json, .xml, .yaml,

.py, .reg) не включены. Это не код, а данные. В них много

легитимного контента, который даёт FP на широкие паттерны.



Если нужно сканировать данные — укажите --ext явно:



cmd

strscan.exe scan C:\\Users --ext .bat,.ps1,.txt,.log

strscan.exe scan D:\\ --ext .js,.json,.xml

Вывод сканирования

Для каждого файла с совпадениями:



text

C:\\Users\\user\\Downloads\\suspicious.bat  (1234 bytes, cp866, bat)

&#x20; \[1] copy%0                         line 5

&#x20;     copy %0 c:\\Windows\\Temp\\svchost.exe

&#x20; \[2] regaddhkcu\\...\\run             line 8

&#x20;     reg add HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run /v X /d ...

Формат: \[номер] паттерн line N + оригинальная строка (если отличается).



С --quiet — только паттерн и номер строки.

С --context N — печатать N строк до/после, помеченных |.



В конце:



text

found: 3 file(s), 7 hit(s)

Пропуск папок

По умолчанию сканер не пропускает ничего. Если указан C:\\ — сканируется

всё, включая Temp, AppData, WinSxS.



Ускорение — через --skip:



cmd

strscan.exe scan C:\\ --skip "winsxs,temp,tmp"

Имена папок регистронезависимые, через запятую. Пропускается папка

с таким именем на любом уровне вложенности.



Рекомендация: пропускайте WinSxS. Это папка с копиями системных

файлов Windows. Сканировать её бессмысленно: файлы дублируют System32.



Логи

\--log FILE пишет лог в файл дополнительно к обычному выводу.



text

2026-09-26 10:49:22 scan start: C:\\Users\\user\\Downloads

2026-09-26 10:49:22 strings: strings\\bad\_commands.txt (52 patterns; all=3, bat=26, ps1=12, vbs=6, js=3, hta=2)

2026-09-26 10:49:25 hit: suspicious.bat line=5 pattern='copy%0'

2026-09-26 10:49:31 done: scanned\_files\_found=1 hits=2

Лог не ротируется. Если сканируете часто, следите за размером.



Если лог лежит внутри сканируемой папки — он попадёт в скан.

Кладите лог вне сканируемой папки.



Что проверено

Пакет 200 BAT-вирусов — 200/200 найдено.



Пакет 30 BAT-вирусов — 30/30 найдено.



USB-червь autorun.bat в автозагрузке — 8 осмысленных хитов.



VS Code, Office, PowerShellGet — без FP в узком режиме.



Что strscan не делает

Не работает с PE-файлами (.exe, .dll, .sys). Для них — утилита sigscan.



Не выносит вердиктов «вирус / не вирус». Только показывает факты.



Не поддерживает регулярные выражения. Только подстроки.



Не поддерживает wildcards. Только точные строки.



Не распаковывает архивы.



Не разворачивает переменные (set a=co; set b=py; %a%%b%).



Не детектирует base64-строки по энтропии.



Не анализирует .lnk (ярлыки).



Ограничения

Только построчный поиск. Нет анализа контекста.



Широкие паттерны дают FP на легитимных скриптах (Office, VS Code,

PowerShell-модули Microsoft). Это ожидаемо: такие паттерны используются

и зловредами, и легитимными программами.



Комментарии в теле базы не сохраняются через CLI.



Логи не ротируются.
