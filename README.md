
# strscan 1.1 — сканер скриптов по списку подозрительных строк

---

## ЧТО ЭТО


strscan — утилита для поиска подозрительных строк в скриптах Windows:
.bat/.cmd, PowerShell .ps1, VBScript, JScript, HTA.

Пользователь ведёт свою базу подозрительных строк (простой текстовый
файл), утилита сканирует файлы, нормализует текст (нижний регистр,
убирает пробелы, убирает комментарии) и показывает, какие строки
и где найдены.

Дополнительно:
- ЭВРИСТИКИ — анализ структуры файла (много коротких set-переменных,
  %random% в путях, длинные base64, циклы goto).
- РАЗВОРОТ set-ПЕРЕМЕННЫХ — для .bat/.cmd утилита разворачивает
  %var% в значения и ищет паттерны в развёрнутом тексте.

Это НЕ антивирус. Утилита не выносит вердиктов «вирус / не вирус».
Она показывает ФАКТЫ: «в файле X найдены строки A, B, C»
или «в файле X обнаружен признак Y». Решение — за пользователем.

Типичные сценарии:
- проверить папку с подозрительным скриптом;
- найти USB-червя на флешке (проверить autorun.inf);
- поискать в автозагрузке вредоносные .bat / .vbs;
- просканировать систему на известные техники зловредов.

strscan дополняет sigscan (PE-сканер):
- sigscan — про PE-файлы (.exe/.dll/.sys) и байтовые сигнатуры.
- strscan — про скрипты (.bat/.cmd/.ps1/.vbs/.js/.hta) и строки.

## БЫСТРЫЙ СТАРТ


1. Посмотреть справку:

     `strscan.exe --help`

2. Добавить паттерн в базу:

     `strscan.exe strings add "copy%0" --section bat`

3. Посмотреть базу:

   `  strscan.exe strings list`

4. Проверить один файл:

     `strscan.exe check suspicious.bat`

5. Просканировать папку:

     `strscan.exe scan C:\Users\user\Downloads --progress`

6. С контекстом (показать строки до/после):

   `  strscan.exe check suspicious.bat --context 2`


### КОМАНДЫ

```
strscan.exe scan <path>
    Просканировать файл или папку по базе строк.

    --strings FILE      база строк (default strings\bad_commands.txt)
    --ext LIST          расширения через запятую
    --no-normalize      не нормализовать текст (точное совпадение)
    --context N         печатать N строк контекста до/после
    --min-hits N        показывать файлы с >= N совпадений (default 1)
    --skip DIRS         пропустить папки (через запятую)
    --min-size SIZE     минимальный размер файла (1K, 100M)
    --max-size SIZE     максимальный размер файла (1M, 2G)
    --limit N           остановиться после N файлов
    --progress          печатать счётчик просканированных файлов
    --quiet             не печатать оригинальную строку и контекст
    --log FILE          лог в файл (дополнительно к stderr)
    --encoding ENC      принудительная кодировка (utf-8, cp866, cp1251)
    --no-notes          отключить эвристики (только паттерны)
    --notes-only        только эвристики, без паттернов
    --no-expand-set     отключить разворот set-переменных для .bat/.cmd
                        (по умолчанию включён)

strscan.exe check <file>
    Проверить один файл (без рекурсии).

    --strings FILE      база строк
    --context N         печатать N строк контекста
    --no-normalize      не нормализовать
    --encoding ENC      принудительная кодировка
    --no-notes          отключить эвристики
    --notes-only        только эвристики
    --no-expand-set     отключить разворот set-переменных

strscan.exe strings list
    Показать содержимое базы строк, разбитое по секциям.

strscan.exe strings add <line>
    Добавить строку в базу (если её там нет).

    --section SEC       секция (all/bat/ps1/vbs/js/hta; default all)

strscan.exe strings remove <line>
    Удалить строку из базы (из всех секций).

strscan.exe strings check <line>
    Проверить наличие строки в базе.

    --strings FILE      база строк (для всех подкоманд strings)
```

## БАЗА СТРОК

База — простой текстовый файл (по умолчанию `strings\bad_commands.txt`).
Формат:
```
    # Комментарии начинаются с #
    # Пустые строки игнорируются.

    [all]
    downloadstring
    net.webclient

    [bat]
    copy%0
    regadd

    [ps1]
    powershell-enc
```

Хранение:
- Строки хранятся КАК ЕСТЬ (с пробелами, если так написали).
- Нормализация применяется только при поиске.
- Дубликаты проверяются по нормализованной форме:
  'copy %0' и 'COPY%0' считаются одинаковыми.
- Регистр не важен, пробелы не важны.

Дефолтная база (default.txt) содержит ~70 паттернов, разбитых
по секциям.

ВАЖНО: комментарии в теле файла (между паттернами) НЕ сохраняются
при редактировании через CLI (strings add / strings remove). Если
добавили свои комментарии в тело базы — правьте файл вручную.


### СЕКЦИИ БАЗЫ

```
  [all]  — паттерны для всех языков
  [bat]  — только для .bat / .cmd
  [ps1]  — только для .ps1 / .psm1 / .psd1
  [vbs]  — только для .vbs / .vbe
  [js]   — только для .js / .jse / .wsf / .wsh
  [hta]  — только для .hta

При сканировании файла выбираются паттерны:
  [all] + секция, соответствующая языку файла.

Пример:
  evil.bat  → ищем паттерны из [all] и [bat]
  evil.ps1  → ищем паттерны из [all] и [ps1]
  Паттерны из [ps1] НЕ ищутся в .bat, и наоборот.

Обратная совместимость:
  Если в файле нет ни одной секции, все паттерны попадают в [all].
```

### ЕСЛИ БАЗА НЕ НАЙДЕНА


Если файл базы (strings\bad_commands.txt) не найден, strscan:

- при обычном сканировании: выдаёт ОШИБКУ и завершается.
- с `--notes-only`: выдаёт ПРЕДУПРЕЖДЕНИЕ и продолжает
  (только эвристики).
- с `--no-notes`: выдаёт ОШИБКУ (нет ни паттернов, ни эвристик).

Если база есть, но пустая — то же самое (ОШИБКА при обычном скане).

Подсказки:
- добавить паттерн:` strings add "copy%0" --section bat`
- скопировать дефолтную базу: `copy strings\default.txt strings\bad_commands.txt`
- сканировать только эвристики: `scan <path> --notes-only`


### ЭВРИСТИКИ

Эвристики — это НЕ паттерны. Паттерны ищут конкретные строки из базы.
Эвристики анализируют СТРУКТУРУ файла и сообщают о подозрительных
признаках. Пользователь сам решает, что делать.

Эвристики выводятся отдельным блоком «Notes» после hits:
```
    suspicious.bat  (589 bytes, utf-8, bat)
      [1] copy%0   line 5
          copy %0 C:\Windows\Temp\svchost.exe

      Notes:
        [!] set-obfuscation: 4 set-переменных в первых 30 строках
                             (4 однобуквенных, 4 коротких) — признак обфускации
        [!] random-path: %random% в имени файла с расширением:
                         2 вхождений (строки 5, 7) — признак самомодификации
```

Список эвристик:
```
  1. set-obfuscation
     Признак: много коротких set-переменных в начале файла.
     Критерий: ≥4 строк 'set ' в первых 30 строках, ≥3 из них
     с однобуквенным именем, ≥2 с коротким значением (1-3 символа).
     Ловит: обфускация через set a=co; set b=py; %a%%b% %0.
     Область: только .bat/.cmd.

  2. random-path
     Признак: %random% в имени файла с расширением.
     Критерий: ≥2 вхождений '%random%' перед расширением
     (.bat/.cmd/.exe/.dll/...).
     Ловит: самомодификация через copy %0 C:\%random%.bat.
     Область: только .bat/.cmd.

  3. long-base64
     Признак: длинная base64-строка (≥60 символов) в подозрительном
     контексте (powershell, -enc, encodedcommand, frombase64string,
     certutil, -decode, -urlcache, iex, invoke-expression,
     downloadstring, downloadfile).
     НЕ срабатывает на: data:image/, data:font/, data:application/
     (встроенные ресурсы), base64 без контекста.
     Ловит: powershell -enc SQBFAFgA..., [Convert]::FromBase64String(...).
     Область: только .bat/.cmd и .ps1/.psm1/.psd1.
     НЕ применяется для .js/.vbs/.hta — там base64 = ресурсы, FP.

  4. goto-loop
     Признак: цикл через goto (метка объявлена, на неё есть
     ОБРАТНЫЙ переход).
     Критерий: ≥1 обратного перехода.
     Ловит: :loop ... goto :loop (зацикливание, самомодификация).
     Область: только .bat/.cmd.

Флаги управления эвристиками:
  --no-notes          отключить эвристики (только паттерны)
  --notes-only        только эвристики, без паттернов
```

### РАЗВОРОТ set-ПЕРЕМЕННЫХ (только .bat/.cmd)

Проблема: обфускация через set НЕ ловится паттернами.

```
    set a=co
    set b=py
    %a%%b% %0
```

Паттерн 'copy%0' НЕ находит эту строку — в тексте '%a%%b% %0'.
Эвристика set-obfuscation СООБЩАЕТ о подозрении, но конкретную
команду 'copy %0' не показывает.

Решение: ДВА ПРОХОДА в scan_file.

  ПРОХОД 1 — ОРИГИНАЛЬНЫЙ текст:
- Ищем паттерны (как обычно).
- Применяем эвристики.
- Находит: reg add, copy %0, %~f0, echo[autorun], ...

  РАЗВОРОТ: expand_set_vars(text) — заменить %var% на значение.
- Собирает все 'set VAR=VALUE' в словарь.
- Для цепочек (set b=%a%py) — несколько проходов.
- Не трогает системные переменные (%APPDATA%, %TEMP%, %RANDOM%,
  %COMSPEC%, %SYSTEMROOT%, ...), %%a (параметры циклов),
  %var:~1,2% (подстроки), set /a (арифметика).

  ПРОХОД 2 — РАЗВЁРНУТЫЙ текст (только если разворот что-то изменил):
- Ищем паттерны ЗАНОВО.
- Эвристики НЕ применяем (дубликаты).
- Находит дополнительно: %a%%b% %0 → copy %0.

  ОБЪЕДИНЯЕМ hits из обоих проходов, убираем дубликаты
  по (pattern, line_no).

Что даёт два прохода:
- Паттерны: всё из оригинала + всё из развёрнутого.
- Эвристики: из оригинала (set a=co видно).
- Ничего не теряем.
- Замедление: ~1.5–2× на .bat (файлы маленькие).

Вывод:
  Если hit найден ТОЛЬКО благодаря развороту, показываем ОБЕ строки:
```
    test_expand.bat  (70 bytes, utf-8, bat)
      [1] copy%0                                    line 4
          %a%%b% %0 C:\Windows\Temp\svchost.exe
          (expanded: copy %0 C:\Windows\Temp\svchost.exe)

  - line_text — оригинальная строка из файла.
  - (expanded: ...) — развёрнутая строка (если отличается).
```

Область применения: ТОЛЬКО .bat/.cmd.

  Для .ps1/.vbs/.js/.py — другой синтаксис ($var =, Execute, eval,
  exec). Отложено.

Флаг:
  `--no-expand-set`     отключить разворот (по умолчанию включён)

Проверено:
- Разворот: %a%%b% %0 → copy %0, паттерн copy%0 находит.
- Регрессии нет: autorun.bat по-прежнему 8 hits.
- Детект вырос: 30 BAT-вирусов — 328 hits (было 170).
- 0 FP на легитимных файлах VS Code, Adobe, NVIDIA.


### ШИРОКИЕ ПАТТЕРНЫ (#wide:)

Часть паттернов в `default.txt` помечена префиксом `#wide:` —
они ИГНОРИРУЮТСЯ по умолчанию.

Это ШИРОКИЕ паттерны: используются и зловредами, и легитимными
программами (Office, VS Code, PowerShell-модули Microsoft).
Дают FP.

Чтобы включить — уберите префикс:

    было:  #wide:invoke-expression
    стало: invoke-expression

Список широких паттернов:
```
  [all]  frombase64string, -encodedcommand
  [ps1]  -executionpolicybypass, invoke-expression, iex(,
         invoke-webrequest, -nop, -noprofile
  [vbs]  createobject("wscript.shell"), wscript.shell
  [js]   activexobject(, wscript.shell, savetofile
```

В [bat] широких паттернов НЕТ — .bat-паттерны специфичны, FP
почти не дают. В [hta] wscript.shell оставлен активным — HTAs
редки, FP мало.


### НОРМАЛИЗАЦИЯ И КОММЕНТАРИИ

По умолчанию текст нормализуется ПЕРЕД поиском:
1. Строки-комментарии пропускаются целиком.
2. Остальные строки приводятся к нижнему регистру.
3. Из строк убираются все пробелы и табы.
4. В нормализованной строке ищется нормализованный паттерн.

Комментарии по языкам (по расширению файла):
```
  .bat .cmd     'rem ...', ':: ...'
  .ps1 .psm1    '# ...'
  .vbs .vbe     "' ..."
  .js .jse      '// ...', '/* ...'
  .hta          '<!-- ...'
  остальные     комментарии не удаляются
```

Почему это работает против самомодифицирующихся скриптов:

  Зловред может дописывать в конец файла мусор вида
      `echo rem %random% %random% >> "%~f0"`
  Это меняет хеш файла при каждом запуске, но НЕ меняет полезную
  нагрузку (copy %0, reg add). Нормализация убирает rem-строки
  и лишние пробелы — а полезная нагрузка остаётся и находится.

Что НЕ работает (но покрывается эвристикой или разворотом):
- Конкатенация через set (set a=co; set b=py; %a%%b% %0).
  → Разворот это ОБНАРУЖИТ и развернёт.
- Шифрование всего скрипта (base64-обфускация).
  → Эвристика long-base64 обнаружит.

С `--no-normalize` нормализация ОТКЛЮЧАЕТСЯ.


### РАСШИРЕНИЯ ПО УМОЛЧАНИЮ

strscan по умолчанию сканирует только РЕАЛЬНО ИСПОЛНЯЕМЫЕ Windows
скрипты:
```
  .bat .cmd         — командные файлы
  .ps1 .psm1 .psd1  — PowerShell
  .vbs .vbe         — VBScript
  .js .jse          — JScript
  .wsf .wsh         — Windows Script Host
  .hta              — HTML Application
```

Текстовые данные (.txt, .log, .ini, .json, .xml, .yaml, .py, .reg)
НЕ включены. Это не код, а данные.

Если нужно сканировать данные — укажите --ext явно:
```
  strscan.exe scan C:\Users --ext .bat,.ps1,.txt,.log
  strscan.exe scan D:\ --ext .js,.json,.xml
```

### ВЫВОД СКАНИРОВАНИЯ

Для каждого файла с совпадениями:
```
    C:\Users\user\Downloads\suspicious.bat  (1234 bytes, cp866, bat)
      [1] copy%0                         line 5
          copy %0 c:\Windows\Temp\svchost.exe
      [2] regaddhkcu\...\run             line 8
          reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v X /d ...

      Notes:
        [!] random-path: %random% в имени файла с расширением:
                         2 вхождений (строки 5, 7) — признак самомодификации

Формат hits: [номер] паттерн line N
             оригинальная строка
             (expanded: развёрнутая строка) — только для .bat/.cmd,
                                                если разворот изменил строку
Формат notes: [!] kind: описание (опционально line N).

С --quiet — только паттерны и номера строк, без контекста.
С --context N — печатать N строк до/после, помеченных |.
С --no-notes — без блока Notes.
С --notes-only — только Notes, без hits.

В конце:
    found: 3 file(s), 7 hit(s), 2 note(s)
```

### ПРОПУСК ПАПОК

По умолчанию сканер НЕ пропускает ничего. Если указан диск C:\ —
сканируется всё.

Ускорение — через `--skip`:

    `strscan.exe scan C:\ --skip "winsxs"`

РЕКОМЕНДАЦИЯ: пропускайте WinSxS. Это папка с копиями системных
файлов Windows. Сканировать её бессмысленно: файлы дублируют
System32.


### ЛОГИ

Флаг `--log FILE` пишет лог в файл дополнительно к обычному выводу.

Формат:
    YYYY-MM-DD HH:MM:SS <сообщение>

Пример:
```
    2026-09-29 10:49:22 scan start: C:\Users\user\Downloads
    2026-09-29 10:49:22 strings: strings\bad_commands.txt (52 patterns; all=3, bat=26, ps1=12)
    2026-09-29 10:49:22 heuristics: enabled
    2026-09-29 10:49:22 expand-set: enabled
    2026-09-29 10:49:25 hit: suspicious.bat line=5 pattern='copy%0'
    2026-09-29 10:49:25 note: suspicious.bat kind='random-path' line=0
    2026-09-29 10:49:31 done: files=1 hits=1 notes=1
```

Внимание:
  - Лог НЕ ротируется. Следите за размером.
  
  

## ЧТО НЕ ДЕЛАЕТ STRSCAN

- Не работает с PE-файлами (.exe/.dll/.sys). Для них — sigscan.
- Не выносит вердиктов «вирус / не вирус». Только факты.
- Не удаляет и не перемещает файлы. Только показывает.
- Не генерирует скрипты очистки (clean.bat).
- Не поддерживает регулярные выражения. Только подстроки.
- Не поддерживает wildcards. Только точные строки.
- Не распаковывает архивы.
- Не анализирует .lnk (ярлыки).


## ОГРАНИЧЕНИЯ

- Только построчный поиск. Нет анализа контекста между строками.
- Широкие паттерны (при включении через `#wide`:) дают FP на
  легитимных скриптах.
- Комментарии в теле базы не сохраняются через CLI.
- Логи не ротируются.
- Эвристики анализируют только структуру, не семантику.
- Разворот set — только для .bat/.cmd. Сложные обфускации
  (for, call set, подстроки) не разворачиваются, но эвристика
  set-obfuscation о них сообщает.
